# 架构

应用由 Go 服务、SQLite 配置库与 Vue 管理界面组成。浏览器和 fnOS 桌面入口只访问本地管理 API；凭据不会返回给前端。

```
Vue 管理界面 → /api/v1 → API 层 → Engine → Provider Registry → 外部服务
                                ↓
                            SQLite Store
```

`media.Adapter` 负责 `Test` 与 `ActiveViewerCount`；`downloader.Adapter` 负责 `Test`、`Stats`、`Limits` 和按方向的 `ApplyLimits`。注册表根据 `kind` 选择具体适配器，未知类型返回明确错误。Service 的组装入口注册内置实现，运行编排依赖接口，不包含厂商认证逻辑；连接周期复用通过可选 `CycleAdapter` 委托。

Service 分别轮询影视库和下载器。影视库采集失败时，相关绑定链回退到其基础速度并记录事件；下载器每轮依据其所属启用绑定链执行限速。

代码依赖保持单向：领域模型不依赖基础设施；影视库、下载器、绑定链与存储只依赖领域模型；服务层负责组合它们；API 直接调用服务和存储，不再经过旧兼容门面。

一台下载器只能属于一个**启用**的绑定链，避免两个规则同时覆盖同一全局限速；同一影视库可同时参与多个链。

自动释放通过 `Release`/`ReleaseDirections` 选择设置策略，再复用按方向的写入和清理流程。手动 `Restore` 固定恢复原值。`release_limits` 快照独立于绑定关系，确保删除后的最高限速仍然可读；外部写入失败不得清理原值。

## 配置修改、限速与停机

`service/coordinator.go` 是单进程写命令的唯一协调入口。API 写请求在读取旧配置之前进入；轮询、手动恢复和自动释放进入后重新加载下载器，避免排队期间删除或修改的旧快照被再次应用。只读 GET 不持有此协调器。

停机顺序为：停止接收命令 → 取消在途命令 → 排空协调区 → 用独立超时释放限速。释放完成后不再允许 API 或轮询写入。更换下载器地址/账号之前，必须先用旧连接释放已接管限速；失败时不保存新连接。

SQLite 使用 WAL、5 秒 busy_timeout、单连接及立即事务。所有游标先读完/关闭，再发起嵌套查询，避免单连接死锁；链成员冲突在事务内复查，事件去重在事务内完成。网络请求不占用 SQL 连接。

这不是跨进程分布式锁；不要运行多个实例控制同一下载器。适配器必须响应 context 取消。旧表迁移采用事务并可重试，成功后清理旧表和旧规则字段；并发测试覆盖删链、改规则、换连接、停机与 SQLite 混合写入。部署和安全边界见 [安全与发布检查](security-and-release.md)。
